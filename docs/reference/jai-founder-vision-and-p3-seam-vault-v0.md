## 4. Three protected seams for compatibility without scope expansion

### Seam 1 — Proposal ancestry is not ledger ancestry

Future N-to-1 graph fan-in may carry one or more **parent_proposal_hash** pointers and an **expected_base_sha** pin. These point to proposed evidence and repository state. They are distinct from **prev_ledger_entry_hash**, which links append-only B1 receipts in chronological integrity order. Do not recycle a proposal pointer as a trusted receipt predecessor, and never substitute a proposal-hash for a B9 human acceptance reference.

Any N-to-1 parent hash array semantics, conflict handling or canonical JCS encoding require a versioned contract and a separately authorized lane. Existing B1 SHA-256 domain separation remains authoritative within its own explicitly routed scope.

### Seam 2 — Optional cohort fan-in

Future **cohort** metadata may group multiple independent candidate lanes for comparison, reversible archival, counterfactual replay or dependency-pulse scheduling. It cannot erase rejected alternatives, deduplicate distinct approval subjects, imply quorum or grant cross-repo writes.

Existing Program 2 A/B/C lane IDs and R1 full_coordinate remain unchanged. The proposal preserves optional compatibility, not a new required field or hidden dependency.

### Seam 3 — Sequential authority gate

1. **Gate 0 — Deterministic chain:** Verify exact canonical bytes, hash link, freshness and read-only evidence integrity before reviewing proposals.
2. **Gate 1 — Scope and Layer 2 == USD 0.00:** Deny wrong repository, bad expected base, unauthorized path, frozen/suspended subject, provider spend or missing authority.
3. **Gate 2 — Proposal synthesis:** Advisory comparison, disagreement, null-result and risk accounting; cannot mutate canonical state or issue B9 acceptance.
4. **Gate 3 — Human finality:** Authenticated VERIFIED_HUMAN_OPERATOR / CONTROL_THREAD issues a distinct decision and authorized route/acceptance. No quorum overrides Gate 0 or Gate 3.

These are candidate evaluation interfaces. No executable gate stack, live authority lease, autonomous Agent ping or provider credentials are installed by the vault.
